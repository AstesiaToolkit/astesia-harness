# AstesiaHarness 需求分析

> 版本: v1.0（分析阶段）
> 日期: 2026-02（本会话）
> 项目: DeepSeek Harness Web GUI 快速启动器（Windows 桌面软件）

---

## 1. 背景与问题陈述

### 1.1 现状

DeepSeek Harness 的 Web GUI 每次使用需要手动完成：

1. 打开一个终端（cmd / PowerShell）；
2. 切换工作目录到 DSH 仓库根目录：
   `cd /d F:\Codes\DownloadProjects\deepseek-harness`
3. 启动服务：
   `pnpm dsh web`
4. 等待服务就绪（前台进程，占用一个终端窗口，不可关闭）；
5. 手动打开浏览器，输入 `http://127.0.0.1:3080`。

### 1.2 痛点

| 痛点 | 说明 |
| --- | --- |
| 步骤繁琐 | 每次 5 步手动操作，重复劳动 |
| 无自动开浏览器 | DSH 自身只打印 URL 就绪行，不自动调起浏览器 |
| 无状态可见性 | 服务是否在跑、端口是多少、是否已就绪，没有直观指示 |
| 无日志查看 | 出错时只能盯着终端，或丢失滚动缓冲区 |
| 无一键停止 | 只能去终端 Ctrl+C，且容易误关窗口导致孤儿进程 |
| 无进程树清理 | pnpm → node → esbuild 子进程链，粗暴结束可能残留 node 进程 |

### 1.3 目标

开发一个 **Windows 桌面启动器（AstesiaHarness）**，实现：

- **一键启动**：后台拉起 `pnpm dsh web`，自动等待就绪，自动打开浏览器；
- **一键停止 / 重启**：彻底清理整个进程树，无孤儿进程；
- **常驻托盘**：状态一目了然，随时可操作；
- **日志与设置**：可查看运行日志，可配置仓库路径、端口、开机自启等。

## 3. 功能需求（FR）

### FR-1 一键启动
后台启动 DSH Web 服务，工作目录为 DSH 仓库根目录，无控制台窗口弹出。
默认命令等价于 `pnpm dsh web`（即 `node --import tsx/esm apps/cli/src/bin.ts web`），可通过设置覆盖。

### FR-2 就绪检测
检测服务真正就绪，而非仅仅进程存活。两种手段：
- **主**：解析子进程 stdout 中的官方就绪行 `dsh web: http://<host>:<port>`（DSH 在 Loader 树稳定后打印，见 `packages/bundle/web-app/src/index.ts`）；
- **兜底**：周期性 HTTP GET `http://127.0.0.1:<port>/`，收到 200 视为就绪。
两者取先到者，避免 stdout 解析失效时卡死。

### FR-3 自动打开浏览器
就绪后自动调用系统默认浏览器打开服务 URL。可通过设置关闭（`autoOpenBrowser`）。
另有手动"打开浏览器"按钮，任何状态可用。

### FR-4 一键停止 / 重启
- 停止：终止**整个进程树**（pnpm → node → esbuild worker），不留孤儿进程；
- 重启：先停止再启动，复用同一套启动流程；
- 停止后保留日志，可继续查看。

### FR-5 状态展示
主界面与托盘图标实时展示服务状态：
`Stopped`（已停止）/ `Starting`（启动中）/ `Running`（运行中）/ `Failed`（失败），
并展示当前 URL、端口、进程 PID、已运行时长。

### FR-6 日志查看
- 主界面滚动日志视图，实时追加子进程 stdout/stderr；
- 环形内存缓冲（如最近 5000 行），可一键清空；
- 可选项：追加写入 `%APPDATA%\AstesiaHarness\logs\dsh-web.log`。

### FR-7 已运行检测（防重复启动）
启动前探测目标端口：
- 若端口已被 **DSH Web 服务**占用（HTTP 200），不重复 spawn，直接进入 `Running` 并打开浏览器；
- 若端口被**其他程序**占用（有监听但非 DSH 响应），提示用户，不强行启动。

### FR-8 设置持久化
JSON 配置存储于 `%APPDATA%\AstesiaHarness\settings.json`，字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `repoPath` | `F:\Codes\DownloadProjects\deepseek-harness` | DSH 仓库根目录 |
| `port` | `3080` | 服务端口（透传 `--port`） |
| `host` | `127.0.0.1` | 绑定主机（透传 `--host`；DSH 拒绝 0.0.0.0） |
| `extraArgs` | `[]` | 附加透传参数（如 `--trusted-host`） |
| `autoOpenBrowser` | `true` | 就绪后自动开浏览器 |
| `startWithWindows` | `false` | 开机自启（以 `--minimized` 启动到托盘） |
| `minimizeToTrayOnClose` | `true` | 关闭窗口时最小化到托盘而非退出 |

### FR-9 托盘常驻
- 托盘图标：恒为用户提供的 app.ico 原图；运行状态通过 **tooltip 文字**表达（Running / Starting / Stopped / Failed），主窗口状态条另有彩色徽标；
- 左键单击：显示/聚焦主窗口；
- 右键菜单：打开浏览器、启动、停止、重启、显示主窗口、退出。

### FR-10 单实例
命名 Mutex 保证同一时刻仅一个实例；重复启动时聚焦已有窗口并提示。

### FR-11 参数透传
设置中可配置额外命令行参数（如 `--trusted-host`），启动时拼接到 `dsh web` 之后。

### FR-12 出错可见
启动失败时给出可读原因并定位到日志，覆盖常见场景：
- pnpm 不在 PATH / 未安装；
- 仓库路径不存在或未安装依赖；
- Node 版本不满足 DSH 要求（^22.19 || >=24）；
- 端口被其他程序占用；
- 前端 dist 未构建（提示运行 `pnpm build`）。

## 5. 边界与非目标（Scope）

**明确不做（v1）：**
- 不管理 DSH profile / 插件 / 配置编辑（那是 DSH 自身职责）；
- 不支持远程访问配置（DSH 本身禁止 `--host 0.0.0.0`，启动器只透传）；
- 不做跨平台（仅 Windows）；
- 不打包/重分发 DSH 仓库本身；
- 不做多实例管理（一次只跑一个 DSH Web 服务）。

**假设：**
- DSH 仓库已完成 `pnpm install`（依赖已就绪）；
- 用户日常通过 `pnpm dsh web` 使用（启动器与其行为一致）；
- 服务端口默认 3080 与 DSH 默认一致，可在设置中修改。

## 6. 验收标准（Acceptance）

1. 双击启动器 → 主窗口出现 → 点击"启动" → 状态转 `Starting` → 自动转 `Running` 并打开浏览器，全程无需打开终端；
2. 服务运行期间，托盘图标为绿色，日志实时滚动；
3. 点击"停止" → 进程树全部结束，无残留 node/pnpm 进程（可用任务管理器验证）；
4. 再次点击"启动"（或重启）可正常重新拉起；
5. 在服务已运行时再点"启动"，不重复 spawn，只打开浏览器；
6. 设置中修改端口并保存后，下次启动使用新端口并打开对应 URL；
7. 关闭主窗口 → 最小化到托盘；托盘右键"退出"彻底退出并（若服务在跑）询问是否一并停止；
8. 单文件发布后，在未安装 .NET 的机器上（若选择框架依赖发布则需 .NET 8 Desktop Runtime）双击可运行。
